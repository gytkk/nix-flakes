# Skill candidates

Use this only after repeated evidence supports `skill` as the best form.

## Naming and scope

- Use lowercase letters, digits, and hyphens.
- Prefer a short action phrase named for the reusable job, not the source project.
- Include the triggering situation, core method, repeatedly needed references, and deterministic scripts only when they materially improve reliability.
- Exclude side quests, unrelated modes, large inline examples, and delivery or orchestration logic that belongs in an automation or runbook.

## Proposal format

- `Name:` suggested slug
- `Description:` one-sentence capability description
- `Why now:` what repeated or broke enough to justify it
- `Inputs:` typical materials the skill reads
- `Outputs:` what the skill should produce
- `Core rules:` 3 to 5 must-have behaviors
- `Bundled resources:` references, scripts, or assets to include
- `Not in scope:` things to keep out of the first version
- `Alternative:` when an automation or runbook is a better fit
